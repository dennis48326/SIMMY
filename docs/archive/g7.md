## 4. Performance
- perf is unavailable; gdb sampler: at 640x480 on llvmpipe the main thread waits for the GPU frame slot
  ~89 % of the time; of the busy part, most is aurora's end-of-frame GX fifo drain and the state cache.
- Found: ENgcRenderStateCache::Apply re-sent every group (9 TEV stages, 8 lights, 4 channels, texgens,
  texture matrices, vertex descriptors) on every dirty bit - the GC's debug "_ngcIgnoreRSCache" path.
  Now (GC behaviour) those cache-owned groups are sent only when they differ from what was last sent;
  the first Apply of each frame and after a full reset (m_dirty 0xFFFFFFFF) sends all. Viewport, scissor,
  blend, z, alpha compare, position matrices and projection are still always sent (other code sets them
  directly). SIMMY_RS_CACHE=0 restores the old behaviour.
- Measured (dev aid SIMMY_FRAME_STATS=1, live mode, 640x480, averages over 300 frames, same binary):
  GX command stream 1.47 MB -> 0.68 MB per frame; game time (update + draw recording) 6.4-6.8 ms ->
  3.8-4.6 ms; aurora end of frame 3.5 -> 1.7-2.6 ms. Wall frame time on llvmpipe is GPU-bound (~82-88 ms
  either way). Pixels identical apart from wall-clock animation (fx_rscache_off_on.png).
- Other per-frame costs seen but left (GC-shaped or small): Apt's string-keyed property lookups
  (AptObject::Find), order-table entry new/delete, PSystemProcess copying its emitter vector.
