## Root cause of "Start never reaches the HUD" (fixed)
- s2c_root's screenMgr.onControllerInput gives a key to the TOPMOST screen with handlesInput and a matching
  player mask, and then stops (unconditional break, see root.dis 0c498). The MOD widget (loaded after H2D) had
  handlesInput true and swallowed every key.
- UIScreenManager::SetHandlesInput passes "0"/"1" strings; cmdProc does Boolean(arg). Our AptVar::ToBool used
  SWF7 rules ("0" -> true). On GC AptGetSwfVersion is ALWAYS 6: AptCharacterAnimationInst::getSwfVersion reads
  AptFile +0xC, which is the .const image ("Apt constant file", no ':' at +8), so the default 6 is used.
  Fix: AptVar::ToBool strings use SWF6 rules (0x hex via strtol, else atof != 0) - src/libaptz/aptvalue.cpp.
  Front end, CAS, memory card dialogs, Continue all re-tested OK. Other version-dependent ops (old Add/Subtract/
  Equals/LessThan/And/Or/StringEquals/ToInteger: undefined handling, see raw AptActionInterpreter.cpp.c
  AptGetSwfVersion callers) are still v7-ish in the port: candidates if a movie misbehaves.
