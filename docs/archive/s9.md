## Tools / how to run
- `s9/shot.sh FRAME NAME "PAD" [ENV=..]` offscreen screenshot -> s9/shots/NAME.png/.log (SIMMY_UI_TRACE on).
  Offscreen runs keep the card in `$S/xdg9/SIMMY/USA/Card A` (aurora userPath = XDG data dir).
- `s9/hl.sh FRAMES NAME "PAD"` headless (fast). Headless has no userPath: the card is `<cwd>/USA/Card A`;
  hl.sh runs from `$S/s9/run`, so the card is `$S/s9/run/USA/Card A`. (Do not run from the build dir: the
  card then lands in /home/claude/apt/build/USA.)
- Fresh card = delete that `USA` folder. A saved card is kept in `s9/card_saved/` (copy to `.../USA`).
- New: with SIMMY_UI_TRACE every G2D dialog prints `[dialog] body | sel0 | sel1` (g2dtarget.cpp).
- `s9/ngh.py <file>` lists/validates a save image's sections (header endianness, CRC); for a .gci strip the
  0x40-byte GCI header first. `s9/lz/t.cpp` round-trips DEFAULT.NGH sections through the LZSS encoder.

## Works
- Fresh card: CreateFileS makes "Sims 2 Save" (147 blocks), banner/icon, then every section, the options
  block, then the 0xDEADBEEF mark. Screenshot of the live mode reached after saving: s9/shots/save2.png.
- File format is GC byte layout: section headers/tables big-endian, CRC-32 over header-as-stored (checksum
  field 0) + compressed data; options block CRC/version BE; ReconBuffer data LE; 'Uix1' SerializeUIGameData.
  Verified with ngh.py: all sections "ok".
- **DEFAULT.NGH checksum solved**: CRC-32 of the section bytes *as stored in the file* (little-endian header,
  checksum field zeroed) + the compressed data. All 55 sections of default.NGH verify. LoadHouseContents now
  checks it (and returns -4 on mismatch, as GC).
- LZSS encoder (Okumura) reproduces the original compressed bytes of DEFAULT.NGH exactly.
- After a save the source is the card cache: houses flushed by WriteToMemoryCard are re-read from the cache
  (big-endian path) when live mode enters the lot (save2.png shows it).
- Load: LoadGameTarget -> SimsMemCardWrap::LoadGame -> MemoryCardCache::LoadCacheFromMemoryCard (whole file,
  per-section CRC check, registry sections to SerializeUIGameData) -> OptionsRecon::ReadIn (CRC, build version)
  -> NghResFile::ReadFromMemoryCard (host, both, thumbnails) -> MainMenuLoadAccept. Screens: s9/shots/load1.png
  (load prompt), load2.png (after load).
