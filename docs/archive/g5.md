## 0. Priority: headless GX fifo overflow (world agent's crash at ~57-64k frames) — fixed
Cause: aurora keeps every GX command the game writes in its fifo buffer (lib/gx/fifo.cpp
write_data_grow, realloc doubling) until aurora_end_frame drains it. `--headless` never initialises
aurora and never opens a frame, so nothing ever drained it: measured 0.23 MB at 300 frames, 134 MB at
3000 frames (~37 KB a live-mode frame) -> uint32 limit (4 GB) -> AURORA_ASSERT "fifo::write_data:
buffer size overflow". Not a leak in the port's draw code (the game issues GX state calls, texture
loads, render-to-texture skin compositing etc. outside the CanDraw guards; with a window they belong
to the next frame).
Fix (src/platform/pc_main.cpp platform_frame_tick): headless only, each tick
`aurora::gx::fifo::clear_buffer()` (aurora internal symbols get_buffer_size/clear_buffer declared in
pc_main.cpp; aurora not modified). The headless "[simmy] N frames" line now prints the fifo size.
Verified: 62,000-frame headless live-mode run, exit 0, fifo 37-52 KB every 300 frames, RSS flat
73-79 MB ($S/g5/long.log, long_rss3.txt). Windowed/offscreen is drained by aurora_end_frame each
presented frame; commands written between frames must NOT be dropped there (tried: dropping them
lost the render-to-texture work). Remaining risk (not reproduced, no display here): a window that
cannot present for a long time (aurora_begin_frame false, e.g. minimised if window::prepare_frame
refuses) still accumulates whatever the game writes outside CanDraw — aurora could expose a "discard
unpresented frame" API; worth a check on Windows (minimise for 20 min).

## 1. Frame effects — done (motion blur, bloom, depth of field)
New: include/simmy/classes/frameeffects.hpp, src/engine/frameeffects.cpp (frameeffects.c,
frameeffectsmanager.c, frameeffectsngc.c, linkonce Bloom/DepthOfField ctors, InterpolateLinear),
src/game/animeventhandlersupport.cpp (HandleBloom/MotionBlur/DepthOfFieldEvent + token overrides).
- FrameEffect state machine (1 off, 2 fading in, 4 on, 8 fading out), per-effect target/current/start
  settings and fades exactly as the GC.
- NGC draws: EFB copy of the 3D window rect into the next XFB (RGB565), motion blur = previous frame
  (EndFrame's half-size copy, GC 8033E9AC, now done in ENgcRenderer::EndFrame) optionally rescaled to
  256>>(level-1); bloom = bright pass (x frameAmp with x2/x4 TEV scale, - threshold, x bloomAmp) at
  128x128 into the scratch buffer; DOF = copy scaled to 256>>level; then the 5-stage TEV blend with
  four half-texel jittered taps (c1 = amount/4) + frame (c2). Vertex data from the disassembly
  (VTXFMT5 pos+uv strips, VTXFMT1 pos+5 uvs).
- ENgcRenderer: XFBs/scratch/previous-frame buffers (InitVideo), GetNextExternalFrameBuffer,
  GetPreviousFrameBuffer, GetCurrentRenderMode, GetFrameEffectsScratchMemory, XFB cycling in Swap.
- Callers: CameraDirector ctor/dtor (FrameEffectsManager Init/Shutdown), ELiveMode::DrawMain ->
  RenderPostProcessEffects (8008BA1C: bloom + blur per player view), ERLevel::Draw (DOF update before
  the foreground list), SAnimator2::eventHandler note kinds 0xD/0xE/0xF -> HandleEffectNote (8005BE08:
  the player's selected sim in social mode, also the other player's in 2P), ESim::Draw
  IsPartOfDOFForeground (80030AC4: selected sim / its social target go to the DOF foreground list,
  drawn sharp after the blur), ESpriteRender::DrawIntoOrderTable (sprites of such sims), CLoadingScreen
  InitAsync/dtor (in-game load: grey DOF 0.3), WorldMap dtor (DOF off).
- What the GC data switches on: DOF in the social stance animations (a2a_*_stanceer_*: stancelover,
  stancefriend, ... rows) and the story intro shots (cam_intro_lotXX_story_part01:
  "socialmodedefault:blurFactor:0.3"), and in-game loading. Motion blur notes in the data
  (motionmax/blackout) name CameraBlurDataElement rows, not FrameEffectsMotionBlurDataElement rows, so
  on the GC only "disable" acts; the director's interpolations (InterpToGameCamera, SetCameraInterpAnim:
  TurnOnMotionBlur) are not ported yet (camera.cpp). No bloom notes at all in the shipped animations
  (only the AbhiTest/ColorShift01/WhiteIntensity rows exist) — bloom is effectively dev-only on GC.
  ENgcRenderer::ProcessFrameEffects / EGraphics bloom+blur parameters are empty on the GC (nothing to
  port). Screen fades: _ngcBrightness only feeds GXSetCopyFilter (no-op in aurora), never changed by
  the game. Lightning: EHouse::TriggerLightningEffect is an empty function (4 bytes) on GC.
- Dev aid SIMMY_FX_FRAME=dof[=row:k:v..],bloom[=row],blur[=level] forces effects on (row default
  "socialmodedefault:blurFactor:0.6", "WhiteIntensity"). SIMMY_GX_PROCESSING=thread|inline|drain.
- Resolution/MSAA/16:9: all copies are GXSetTexCopySrc/Dst in logical 640x480 units, aurora scales them
  to the internal resolution and resolves MSAA (resolve_pass_into). 16:9: the effect quads cover the
  3D view, so g_displayMap2D is switched off around them. Split screen: the 3D window rect of each
  player (E3DWindow +0x220) selects the half.
- Shots: outputs/fx_dof.png, fx_bloom.png (before|after, 640x480), fx_1080p_16x9_msaa4_dof_bloom.png.
