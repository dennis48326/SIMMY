## Design

* **Settings** (`src/platform/pc_settings.{hpp,cpp}`): defaults < `simmy.ini` (next to the exe, or
  `--config`, or `SIMMY_INI`) < `SIMMY_GFX="k=v;k=v"` / `SIMMY_GFX_<KEY>` / legacy `SIMMY_BACKEND` <
  command line (`--key value`, `--key=value`, `--fullscreen`, `--windowed`, `--widescreen`, `--vsync`,
  `--novsync`). Keys: window, fullscreen, resolution, aspect, hud, msaa, anisotropy, vsync, fps_cap,
  backend, resampler. `simmy.ini.example` at the repo root; CMake copies it next to the exe once
  (tools/copy_if_missing.cmake, never overwrites).
* **Defaults reproduce the old behaviour exactly**: config fields that were zero stay zero (window 0 ->
  aurora's 1280x960, msaa 1, anisotropy 0 -> aurora's 16, vsync false), no VISetFrameBufferScale,
  viewport policy untouched. Verified: front end frame 500 bit-identical to a base34 build; live mode
  frame 2400 identical except wall-clock animated pixels (clouds, tree sway, the Sim's idle pose —
  the game is wall-clock timed so no two runs agree there, base vs base included).
* **Render resolution**: `VISetFrameBufferScale(height/480)`. Aurora sizes the EFB as 640x480*scale,
  widened to the native aspect under the STRETCH policy. Viewports, scissors and GXCopyTex
  rectangles/destinations are scaled by aurora from the logical 640x480 (gx.cpp map_logical_*,
  GXFrameBuffer.cpp scale_copy_dst), so EFB copies are made at the internal resolution.
* **Widescreen** (`aspect=16:9`, `pc_splitscreen.cpp`): single-player frames use the STRETCH policy
  (as the wide split mode did) and `split_screen_aspect()` (EGraphics::GetScreenAspect) returns the
  frame aspect, so live mode, CAS, the camera and the loading screen project Hor+ (their vertical FOV
  is computed from 640x480, unchanged). Everything else drawn in 640x480 coordinates would be
  stretched, so `ENgcRenderStateCache::Apply` (the one place all game GX viewport/scissor state goes
  out) calls `display_map_viewport`, which maps viewport+scissor into the 4:3 centre unless the draw
  is a perspective projection whose aspect equals the frame's (for its viewport). Split frames keep
  the old code path (mapping off), so gc/4x3/wide split are unchanged.
* **HUD** (`pc_hud.cpp`): `AptDisplayList::render` calls `simmy_apt_hud_enter/leave` around each
  instance; the anchor is decided top-down from the instance's visible stage bounds (computed like
  the player's ContentBounds, visible children only) and inherited by its subtree.
  - both modes: a shape drawn wider than the stage on both sides -> "bleed" (the pause menu's
    `blackPoly` dimmer is -320..960: the GC artists drew it oversized, so it now covers the side
    bars; drawn at the 4:3 scale, the mapping moves from the viewport into the projection,
    clip x' = a*x + b*w, viewport/scissor full width); an untextured shape covering exactly the
    stage width -> stretched to the frame width.
  - hud=edges: bounds in the left half -> left edge, right half -> right edge, compact across the
    middle -> centred with its subtree (dialogs, the pause menu), wide container -> if all of its
    children that have a side agree (and none is centred) the group goes there (the clock/money bar:
    its clock text field box is 98..698), else its children are decided one by one.
  - The anchor is a horizontal viewport shift (±side bar) applied by display_map_viewport; Apt
    coordinates, hit tests and the interpreter are untouched. `SIMMY_HUD_TRACE=<game frame>` logs
    the decisions of that frame.
* **MSAA / anisotropy / vsync / backend / fullscreen**: AuroraConfig fields; the backend is now passed
  in windowed mode too. Exclusive fullscreen uses SDL_SetWindowFullscreenMode with the closest display
  mode (window= size, else the desktop's); borderless = SDL fullscreen with no mode. Alt+Enter toggles
  (pc_main.cpp platform_pump_events, AURORA_SDL_EVENT key-down).
* **Frame cap**: the game measures frames in 60 Hz retraces (EEngine::RetraceUpdate clamps to >= 1),
  so faster frames would speed the game up. The pacing sleep in platform_frame_tick stays the frame
  limiter; fps_cap only lengthens it to 2/3/4 retraces (30/20/15), values above 60 or "off" clamp to
  60. With vsync on a 120/144 Hz display presents block at the display rate but frames still come at
  60 Hz — game speed unchanged.
* **Screenshots with MSAA**: aurora disables its whole readback system when msaa > 1
  (gfx/readback/gpu.cpp initialize). pc_main.cpp then uses aurora's public pass API instead:
  `aurora::gfx::resolve_pass` (single-sample snapshot), an encoder task copying it to a MapRead
  buffer, MapAsync after submit. Without MSAA the old AuroraReadbackCaptureColor path is used.
* Test switch `SIMMY_GFX_LOWRES_UNTIL=N`: render at scale 1 until presented frame N, then switch to the
  configured resolution (llvmpipe at 1080p+4xMSAA runs ~1 frame/s; also exercises a mid-game EFB
  resize).

## Limitations

* With msaa > 1 aurora's readback is off: `ENgcRenderSurface::GetImageData/CopyToTexture` (CPU reads
  of render-to-texture copies) and any GXPeek-style readback get no data. Nothing in the game calls
  these yet (only pc_devtools' render-surface test), but they will need aurora support for MSAA
  readback (resolve before gather) when e.g. the photo/thumbnail features are ported.
* Render surfaces (`ENgcRenderSurface`, GXCreateFrameBuffer) render at their own pixel size, not the
  internal resolution: aurora's logical size inside an offscreen pass is the pass size. Unused by the
  game so far.
* The frame effects that copy the EFB (motion blur, bloom, depth-of-field, the censor blur, sim
  shadows) are not ported yet (stubs: EGraphics::SetMotionBlur/SetCameraBloom, ProcessFrameEffects,
  ESim shadow), so there is no EFB-copy effect in the game to check; the scaling path they will use
  (GXSetTexCopySrc/Dst + GXCopyTex in logical units) is aurora's and scales with the EFB.
* hud=edges is heuristic: a HUD piece split across sibling instances on both sides of the middle
  keeps its pieces apart; slide-in animations from off-stage can switch anchor mid-animation; masks
  are anchored with their own instance.
* Text the game places in screen space from 3D positions (none ported yet) would be placed in the
  4:3 mapping, not the wide 3D view.
* VILockAspectRatio is not implemented in aurora, so aspect=16:9 follows the window's own aspect
  (16:9 by default); there is no letterboxing to force 16:9 in a 16:10 window.
* Windowed mode, fullscreen and Alt+Enter could not be exercised here (no display); the backend
  choice was exercised offscreen.

## Verification (llvmpipe, OpenGLES backend, offscreen)

* No settings: front end frame 500 bit-identical to a base34 build; live mode frame 1910: 716 of
  307200 pixels differ, all on wind-swayed trees / the Sim's idle outline (wall-clock animation);
  HUD and static scene identical (outputs/gfx_default_live_*.png, diffmask).
* Split screen gc / 4x3 / wide (SIMMY_TWO_PLAYER=1) new vs base34: identical framing, aspect and HUD
  placement; differences only in time-animated content (and game-time lighting in the wide run,
  whose house loaded 300 frames earlier) — outputs/gfx_split_*_new_vs_base34.png.
* 1080p 16:9 4x MSAA (window 1920x1080): CAS, live (hud centered / edges), pause menu (centered /
  edges; the dimmer covers the side bars), buy mode — outputs/gfx_1080p_*.png.
* Render resolution change at runtime (SIMMY_GFX_LOWRES_UNTIL) works mid-game.

  simmy_apt_hud_enter/leave).

  projection switch. Behaviour with the flag off is unchanged (same GX calls, same values).

  simmy_apt_hud_enter after appendVertexMatrix, simmy_apt_hud_leave after render.
