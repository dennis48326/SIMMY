## 1. "View Painting" sim glitch — root cause found and fixed
Not animation/skinning. Instrumented EAnimController (track list, blend list, per-node states, joint
world positions = pivot through the node matrix / controller scale 1/4096): the pose was always sane
(arms down, face forward, every joint within 0.25 of the root). Drawing without walls showed the whole
sim. Cause: SAnimator2::positionCharacter (PC deviation since the first port) added the house position
(EHouse +0x4C/+0x50 = DAT_80475E70 = 0.5, 0.5) to the sim's engine position. The GC (80065094) does not:
the animation-format position is in 1/16 tiles with a tile's centre at +8 (e.g. 248 = 15.5), i.e.
already a world position whose tile edges are integers (walls at x=26 ± 0.05). The house offset only
centres the objects (ISimsObjectModel::SetObjOrient uses the integer tile + 0.5). So every sim was drawn
(0.5, 0.5) off: the painting repro sim stood exactly on the wall line (26.00, 16.00) facing away from it,
so everything behind the wall plane (upper arms, head, back of the torso; one leg partly) was hidden by
the wall's depth, the parts slightly forward (hands, shirt front, toes) showed — "arms/face missing,
stretched leg". Intermittent = which way the sim faced / which idle it played next to the wall.
Same bug: sitting (sim inside the sofa's back: outputs/fx_sofa_sit_fixed.png), any use of an object slot.
Fix: positionCharacter no house offset (faithful), ESim::GetSimPos (PC helper, camera centring / fade)
likewise. Shots: outputs/fx_view_painting_fixed.png (before | after), fx_sofa_sit_fixed.png,
fx_bed_sleep_after_fix.png (head on the pillow).
Checked on the way (all faithful vs the raw): EAnimController Compute/Animate/Blend/BlendNodeArrays/
ComputeMatrices/CalcMatrix, SAnimator2 index arrays (match the .bss addresses), SimRenderer::MorphParts.

## 2a. Floor per-vertex lighting — done
ifloor.cpp: BuildTable now also emits the light strips (a room's run down a column, AddLightStrip;
GC's local_68 logic), BuildVertexSpans 800457B0 (per column the covered light-grid vertices -> runs;
the GC's two rolling 64-bit masks give the same runs), EvaluateFloorColors 800462F8,
EvaluateLightAtVertices 800463A4 (<= 4 nearest point lights of the room: colour x cosine (height /
distance) x min(1, (range/distance)^2)), EIFloor::DoLightingCalculation 80046614 (strip vertex colours
= point light x diffuse x 128 + (ambient x material ambient + sun x diffuse) x 128, clamp 255, alpha
0x80; half-tile ends ported). CreateFloors builds each floor's spans (PC: an outside floor takes all
outside rooms' light strips, the GC strips carried the lighting room). The display lists reference
the colour arrays (TriStripRef), so the per-frame rewrite shows directly. EvaluateFloorLights was
already in roomlights.cpp (g4). EFloorVertexSpan is 3 bytes (x, first, last); overrides.tsv: the 4
signatures. Result: floors follow the time of day and lamps light pools on the floor
(outputs/fx_floor_light.png: night, before | after).

## 2e. Particle quads: display-list and reflection paths — done
ENgcRC::QuadList (deferred) builds a GX display list when _ngcUseGXDisplayList (GX_QUADS|VTXFMT7,
as GC's CreateGXDisplayList ORs format 7), ENgcRenderer::QuadList executes it (GXSetArray strides
16/4/4/8|16, TEX1 at uvs+8) and has the reflective path (ReflectionCoord sphere-map uvs, direct).
PC guard: a list recorded with two uv sets is sent directly when the shader turned the second off
(the indices would not match the descriptor). The effects system draws immediate, so in practice the
direct path still runs (shower steam checked).
